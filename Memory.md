# Memory.md

Долговременная память проекта. Контекст, а не контракт: при конфликте приоритет у кода и артефактов `docs/agent/` (см. `AGENTS.md`, §4).

## Что это за проект

Каркас агентного workflow разработки. Прикладного кода пока нет: `src/` и `tests/` пусты. Продукт проекта — сам процесс: три роли (Архитектор / Кодер / Ревьювер), которые обмениваются файлами-артефактами в `docs/agent/`.

- Правила: `AGENTS.md`
- Протокол итерации: `.agents/ORCHESTRATOR.md`
- Роли: `.agents/prompts/01-analysis.md`, `02-implementation.md`, `03-review.md`
- Адаптер Superpowers: `.agents/adapters/superpowers.md`
- Контрактные артефакты: `docs/agent/PROJECT_SPEC.md`, `IMPLEMENTATION.md`, `REVIEW_REPORT.md` (на момент инициализации пусты)

## Устойчивые решения по каркасу

- **Канонический `БЛОК 0.1 КОНВЕНЦИЯ ИДЕНТИФИКАТОРОВ` живёт в `.agents/prompts/01-analysis.md`.** Он самый полный (столбец «Область жизненного цикла» + 13 правил). В `02-implementation.md` и `03-review.md` блок обязан быть текстово идентичен. При правке менять все три файла одновременно — на этом утверждении построен `ORCHESTRATOR.md:7`.
- **Нумерация идентификаторов (`REQ-`, `REV-`, `DEC-`, `CONFLICT-` и остальных) — сквозная в пределах проекта, а не одного артефакта.** Это единственная трактовка, совместимая с правилом 5 (при `REOPENED` `REV-` сохраняет исходный ID) и со стабильностью ID между итерациями. Прежние формулировки «нумерация сквозная в пределах одного артефакта / одного `REVIEW_REPORT`» в 02 и 03 были устранены как противоречащие правилу 5.
- **Блок `VERDICT` в `03-review.md` определён ровно один раз.** Ранее он был продублирован (четыре вердикта описывались дважды) — дубль удалён.
- **Подавление bootstrap Superpowers** описано в `.opencode/INSTALL.md`. Политика: bootstrap активен только в сессии Кодера, в сессиях Архитектора и Ревьювера подавляется.

## Проверка

Кодовой базы, сборки, тестов и линтера в проекте нет, поэтому `build`/`typecheck`/`lint`/`tests` для правок каркаса — `NOT_APPLICABLE`. Проверка правок каркаса выполняется структурно: текстовое равенство `БЛОК 0.1` в трёх промтах, единственность `VERDICT`, отсутствие висячих ссылок.

## Открытые вопросы

- Конкретный способ подавления bootstrap Superpowers в opencode зависит от версии и конфигурации установленного Superpowers — здесь он не зафиксирован (внешний harness).
