# Memory.md

Долговременная память проекта. Контекст, а не контракт: при конфликте приоритет у кода и артефактов `docs/agent/` (см. `AGENTS.md`, §4).

## Что это за проект

Каркас агентного workflow разработки. Прикладного кода пока нет: `src/` пуст; `tests/` содержит только deterministic harness. Продукт проекта — сам процесс: три роли (Архитектор / Кодер / Ревьювер), которые обмениваются файлами-артефактами в `docs/agent/`.

- Правила: `AGENTS.md`
- Протокол итерации: `.agents/ORCHESTRATOR.md`
- Роли: `.agents/prompts/01-analysis.md`, `02-implementation.md`, `03-review.md`
- Адаптер Superpowers: `.agents/adapters/superpowers.md`
- Контрактные артефакты: `docs/agent/PROJECT_SPEC.md`, `IMPLEMENTATION.md`, `REVIEW_REPORT.md` — волатильные, перезаписываются каждой итерацией; runtime workflow state — в `docs/agent/STATE.md` (см. «Runtime State» ниже)

## Runtime State

Runtime workflow state в `Memory.md` не хранится.

Канонический источник runtime state:

docs/agent/STATE.md

Правило: `Memory.md` MUST NOT содержать volatile workflow state (текущее состояние, счётчики, verdict, commit SHA текущей итерации).

## Устойчивые решения по каркасу

- **Канонический `БЛОК 0.1 КОНВЕНЦИЯ ИДЕНТИФИКАТОРОВ` живёт в `.agents/prompts/01-analysis.md`.** Он самый полный (столбец «Область жизненного цикла» + 13 правил). В `02-implementation.md` и `03-review.md` блок обязан быть текстово идентичен. При правке менять все три файла одновременно — на этом утверждении построен вводный блок `ORCHESTRATOR.md` (абзац про идентичность `БЛОК 0`).
- **Нумерация идентификаторов (`REQ-`, `REV-`, `DEC-`, `CONFLICT-` и остальных) — сквозная в пределах проекта, а не одного артефакта.** Это единственная трактовка, совместимая с правилом 5 (при `REOPENED` `REV-` сохраняет исходный ID) и со стабильностью ID между итерациями. Прежние формулировки «в пределах одного артефакта» (`PROJECT_SPEC` в 01, `IMPLEMENTATION` в 02, `REVIEW_REPORT` в 03) устранены из всех трёх промтов как противоречащие правилу 5.
- **Блок `VERDICT` в `03-review.md` определён ровно один раз.** Ранее он был продублирован (четыре вердикта описывались дважды) — дубль удалён.
- **Ограничение Superpowers ролью Кодера — универсальное и harness-независимое** (`AGENTS.md` §9, адаптер §22). Базовый уровень нормативный: вне сессии Кодера скиллы игнорируются, роли работают только по своим промтам; правило опирается на обязательное чтение `AGENTS.md` и промта роли. Техническое подавление bootstrap — опциональное per-harness усиление (для opencode — `.opencode/INSTALL.md`).
- **Один execution-layer на роль** (решение 2026-09-27): Superpowers — слой Кодера; mattpocock/skills ([mattpocock/skills](https://github.com/mattpocock/skills), MIT) — слой Архитектора с allowlist v1 (`grilling`, `to-questionnaire`, `research`, `grill-me`; роутер `ask-matt` ограничен навигацией; см. `.agents/adapters/mattpocock-skills.md` §2); Ревьювер принципиально без слоя — независимость. Установка mattpocock/skills — редактируемыми копиями через skills.sh в репозиторий: адаптация под контракт важнее следования upstream, дрейф принят осознанно; managed-плагин Claude Code отвергнут (read-only). Субординация: при конфликте формата/процесса скилла с контрактом (артефакты-файлы в `docs/agent/`, конвенция идентификаторов) контракт побеждает. `AGENTS.md` §9 обобщён до «Execution-Layer Integrations».
- **Первый полный цикл протокола (Архитектор → Кодер → Ревьювер) прогнан 2026-09-27** на задаче вендоринга `to-questionnaire`/`research`; вердикт `APPROVED_WITH_CHANGES`, ветка `iteration/dry-run` смержена в `main` (коммиты `df160b2` → `9875a69` → `c42665d`). Подтверждено: протокол работоспособен на декларативных задачах; grilling-интервью (`Q-001`–`Q-005`) адекватно заменило сбор требований. Все три роли исполнялись одной средой — зафиксированное в `REVIEW_REPORT` ограничение независимости. Итерация 2 закрыла `REV-001`–`REV-003` через `Review Item Resolution`, вердикт `APPROVED` (`4bec754` → `912f99b`): путь итерации N+1 и механизм закрытия замечаний валидированы.
- **Формальная workflow state machine внедрена 2026-09-27** (патч из `code review.md`): канонические transitions — `.agents/STATE_MACHINE.md` (нормативен; промты ролей transitions не переопределяют, только описывают работу внутри разрешённого состояния); runtime state — только `docs/agent/STATE.md` (счётчики: cycle, architecture_revision, implementation_iteration, review_iteration, no_progress_count); исполнение — Execution Loop в `.agents/ORCHESTRATOR.md` (раздел 2) + STATE GATE и COMPLETION GATE в промтах ролей; verdict routing — в ORCHESTRATOR (разделы 4–5: `REJECTED` — только architecture-level failure); Q-* без safe ASM-* → `WAITING_HUMAN`, silent downgrade запрещён; `POTENTIAL` — статус доказательности, не severity.
- **Enforcement-слой внедрен 2026-09-27** (второй патч из `code review.md`, post-patch audit): `docs/agent/STATE.md` синхронизирован с фактической историей — `COMPLETED`, cycle 1, implementation iteration 2, review iteration 2, verdict `APPROVED` (SHA — `df160b2` / `9875a69` / `4bec754` / `912f99b`); framework-invariants живут в `.agents/HARNESS_CONTRACT.md` (REQ-HARNESS-001..023 + mapping на валидаторы), а не в `PROJECT_SPEC`. Семантика коммитов state: двухфазная модель (сначала artifact commit, затем `State N: <transition>` с обновлённым STATE.md; STATE.md MUST NEVER ссылаться на несуществующий SHA — ORCHESTRATOR §11). `STATE.md` — runtime metadata: baseline-диффы исключают его (exclusion list в HARNESS_CONTRACT). Агрегат — `tests/harness/check-all.sh` (4 валидатора + `run-fixtures.sh` — 8 unit fixtures §46); `check-state.sh` семантический (per-state invariants, verdict routing, subject/нумерация коммитов, HALTED/WAITING_HUMAN); `check-contracts.sh` глобальный (docs/ + .agents/*.md + Memory.md + AGENTS.md + README.md; prompts и tests/harness явно исключены). CI — `.github/workflows/harness.yml` (fetch-depth 0). **`df160b2` — de-facto Architecture 1** (неконформное сообщение `docs(agent):`, история не переписывается): зафиксирован явным exemption в `check-state.sh` и `check-git-protocol.sh` — при появлении настоящего `Architecture 1:` коммита проверка упадёт на дубликате, сигнализируя устранить неоднозначность.

## Проверка

Кодовой базы, сборки, тестов и линтера в проекте нет, поэтому `build`/`typecheck`/`lint`/`tests` для правок каркаса — `NOT_APPLICABLE`. Проверка правок каркаса — deterministic harness: `bash tests/harness/check-all.sh` (идентичность `БЛОК 0`, семантика STATE.md, глобальные идентификаторы, git protocol, negative fixtures). CI прогоняет тот же агрегат на push/PR (`.github/workflows/harness.yml`, `fetch-depth: 0`); статус читается из терминала без браузера: `gh run list --limit 3` (gh CLI 2.101+, авторизация — device flow, токен в keyring). Конвенция доказательств в артефактах: команды проверок приводятся в код-блоках, а не в ячейках таблиц — экранирование пайпов в GFM-таблицах ломает копируемость команды (вывод из REV-003).

Коммит-конвенция: артефактные коммиты итераций — строго `Architecture N:` / `Iteration N:` / `Review N:` (GIT-ПРОТОКОЛ, `02-implementation.md` §15; форматы продублированы в `ORCHESTRATOR.md`, раздел 2); правки каркаса вне итераций — обычные conventional-коммиты. Известное отклонение: спека итерации 1 закоммичена как `docs(agent): ...` до появления формата в оркестраторе — история не переписывается.

## Открытые вопросы

- Конкретный способ подавления bootstrap Superpowers в opencode зависит от версии и конфигурации установленного Superpowers — здесь он не зафиксирован (внешний harness).
- `domain-modeling` из mattpocock/skills отложен до первой доменно-тяжёлой итерации (подтверждено 2026-09-27). Зависимость — 3 файла (`SKILL.md` + `CONTEXT-FORMAT.md` + `ADR-FORMAT.md`). Направление адаптации при включении: глоссарий → `docs/architecture/GLOSSARY.md` (курируемая документация, не артефакт итерации); механизм ADR вырезать — решения только через `DEC-` в спеке, переняв тройной критерий ADR (трудно обратимо + удивительно без контекста + реальный trade-off) как фильтр фиксации `DEC-`; `CONTEXT-MAP`/мульти-контекстность не вводить. Из allowlist вендорены `grilling`, `to-questionnaire`, `research` — адаптированными копиями в `.agents/skills/` (вывод сразу в `Q-*`/`ASM-*`/секции спеки по `DEC-002`–`DEC-004`); `grill-me` не вендорится, покрыт `grilling` (`DEC-001`). Привязка к harness (правило — адаптер §4): для ZCode подтверждена 2026-09-27 — все три скилла обнаруживаются из workspace `.agents/skills/` и попадают в список доступных с адаптированными описаниями (файловые пути в списке указывают на вендоренные копии); user-scope теней нет (`~/.zcode/skills` и `~/.agents/skills` пусты). Кросс-harness поведение флага `disable-model-invocation`: ZCode игнорирует (скилл в списке), Kimi Code молча исключает скилл из обнаружения (приёмочный прогон 2026-09-27: 4/4 smoke-теста, кроме регистрации `to-questionnaire`; остальное — PASS, включая правило ролей и форматы коммитов). Флаг снят с вендоренной копии ради переносимости; повторная проверка регистрации в Kimi Code — после обновления рабочей копии. Для сред без сканирования `.agents/skills/` — symlink, не копия.
