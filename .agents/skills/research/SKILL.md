Исследуй вопрос по **первоисточникам** и не блокируй основную работу.

1. Ищи по **первоисточникам** — официальная документация, исходный код, спецификации, first-party API, — а не по их пересказам. Каждое утверждение веди к источнику, которому оно принадлежит.
2. Если среда поддерживает фоновый поиск (фоновые агенты, параллельные задачи) — используй его и продолжай основную работу. Идущий поиск — незакрытая предпосылка только для вопросов, которые от него зависят; остальная работа не ждёт.
3. Находки фиксируй с цитатой первоисточника для каждого утверждения.

## Фиксация результата (адаптация под контракт)

* Находки переносятся в предметные секции `PROJECT_SPEC` — архитектурные решения (`## 5. Architecture Decisions`), выбор стека (`## 6. Technology Stack`), зависимости и ограничения (`## 16. Dependencies`) — каждое утверждение с указанием первоисточника: URL, путь в репозитории или команда с выводом.
* Отдельных закоммиченных файлов исследование не создаёт; черновик, если нужен, — некоммитимый рабочий файл вне `docs/agent/`.
* Доказательность — `БЛОК 0.5`: неподтверждённое утверждение помечается `NOT_TESTED`/`POTENTIAL`, а не выдаётся за факт; версии библиотек, значения конфигурации и ответы внешних систем не выдумываются (`БЛОК 0.3`).
* Среда без сетевого доступа: деградируй до локальных фактов (репозиторий, команды) с явной пометкой ограничения; недоступное фиксируй как `Q-`/`ASM-`, а не пропускай молча.
* Правило upstream «сохрани findings отдельным файлом туда, где репозиторий хранит заметки» заменено контрактом «артефакт итерации один» — это и есть намеренный дрейф.
