# Адаптер mattpocock/skills — execution-layer Архитектора

## Назначение

Этот адаптер подключает набор скиллов [mattpocock/skills](https://github.com/mattpocock/skills) (MIT) к production-процессу проекта.

Скиллы используются как **внутренний execution layer Архитектора** (execution-only): дисциплина выяснения и уточнения требований до начала проектирования.

```text
Требования пользователя
     ↓
grilling / to-questionnaire / research   ← mattpocock/skills
     ↓
PROJECT_SPEC (REQ-*, Q-*, ASM-*, DEC-*)
     ↓
docs/agent/PROJECT_SPEC.md
```

Набор не заменяет:

* промт роли `.agents/prompts/01-analysis.md`;
* контракт артефактов: `PROJECT_SPEC` — файл `docs/agent/PROJECT_SPEC.md`;
* конвенцию идентификаторов (`REQ-`, `ASM-`, `Q-`, `DEC-` и остальные, `БЛОК 0.1` промтов);
* решения Архитектора: скилл уточняет входные данные, но не проектирует сам;
* `ORCHESTRATOR.md` и протокол итерации.

Скиллы mattpocock/skills несут собственные мнения о процессе (issue-трекеры, тикеты, `CONTEXT.md`, ADR). Всё, что конфликтует с контрактом проекта, в сессии Архитектора запрещено; перечень — в §2.

---

## 1. ИЕРАРХИЯ ИСТОЧНИКОВ ИСТИНЫ

При конфликте побеждает проект, а не скилл:

1. фактическое состояние репозитория и вывод команд;
2. контракт артефактов (`docs/agent/`);
3. `AGENTS.md` и промт роли `.agents/prompts/01-analysis.md`;
4. этот адаптер;
5. инструкции скилла.

Если формат вывода скилла (публикация спеки в трекер, отдельный файл `CONTEXT.md`, ADR) противоречит контракту проекта — результат оформляется по контракту: артефакт один, `docs/agent/PROJECT_SPEC.md`; вопросы и допущения — `Q-*` и `ASM-*` в его секциях; архитектурные решения — `DEC-*` в нём же.

## 2. РАЗРЕШЁННЫЕ И ЗАПРЕЩЁННЫЕ СКИЛЛЫ

Проектная политика v1. Имена соответствуют репозиторию `mattpocock/skills`.

| Скилл | Тип | Статус | Обоснование |
| --- | --- | --- | --- |

| `grill-me` | user-invoked | Покрыт | Не вендорится: user-invoked обёртка над `grilling`; trigger-фразы уже включены в описание вендоренной копии (`DEC-001`; якорь — §4). |

## 3. ОГРАНИЧЕНИЕ РОЛЬЮ

У mattpocock/skills нет SessionStart-bootstrap: user-invoked скиллы запускаются командой, model-invoked срабатывают по релевантности. Действует то же универсальное правило (`AGENTS.md`, §9):

* в сессии **Архитектора** разрешены скиллы из allowlist §2, работа идёт по `.agents/prompts/01-analysis.md`;
* в сессиях **Кодера** и **Ревьювера** скиллы mattpocock/skills игнорируются: Кодер работает по `.agents/prompts/02-implementation.md` со своим слоем (Superpowers), Ревьювер — по `.agents/prompts/03-review.md` без скиллов вообще;
* техническое подавление — опциональное per-harness усиление (не устанавливать скиллы в профили чужих ролей там, где harness их разделяет); нормативный уровень первичен.

Ревьювер без execution-layer — намеренно: независимость ревью — его ценность.

## 4. УСТАНОВКА

Upstream предлагает два взаимно исключающих способа:

* managed-плагин Claude Code — **не используется**: read-only, адаптация под контракт невозможна;
* установщик `npx skills add mattpocock/skills` — **выбранный путь**: редактируемые копии скиллов в репозитории.

Правила:

1. Устанавливать только скиллы из allowlist §2.
2. Редактируемые копии адаптируются под контракт: вывод `grilling` — сразу в форматы `Q-*`/`ASM-*`.
3. Дрейф копий от upstream принят осознанно: адаптация под контракт важнее свежести; обновление — ручное (`npx skills update`) с повторной сверкой §2.

Текущее состояние установки:

* `grilling` — вендорен адаптированной копией: `.agents/skills/grilling/SKILL.md` (источник upstream: `skills/productivity/grilling/SKILL.md`);
* `to-questionnaire` — вендорен адаптированной копией: `.agents/skills/to-questionnaire/SKILL.md` (источник upstream: `skills/productivity/to-questionnaire/SKILL.md`);
* `research` — вендорен адаптированной копией: `.agents/skills/research/SKILL.md` (источник upstream: `skills/engineering/research/SKILL.md`);
* `grill-me` — не вендорится, покрыт `grilling` (§2, `DEC-001`).

Привязка к harness:

* в средах со workspace-discovery пути `.agents/skills/` (например, ZCode) привязка выполняется самим расположением каталога — отдельных настроек не требуется;
* в средах с собственной директорией скиллов (Claude Code, opencode) привязка — symlink на `.agents/skills/<name>`, а не копия: адаптированная версия должна существовать в одном экземпляре.

## 5. ГЛАВНОЕ ПРАВИЛО АДАПТЕРА

mattpocock/skills отвечает на вопрос:

> **Как эффективно выяснить и уточнить требования?**

Production-контракт отвечает на вопросы:

> **Что именно проектировать?**

> **В каком виде фиксировать результат?**

Скилл уточняет вход. Спецификацию создаёт Архитектор по `.agents/prompts/01-analysis.md`.
